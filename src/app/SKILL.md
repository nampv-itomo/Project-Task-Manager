# src/app — route map & shell

Layout shell (`layout.tsx`): `<Providers>` → `AppShell` (`height="fill"`, `contentPadding={0}`, `sideNav={<AppNav />}`) → page. `AppShell` builds the skip link, the `<main>` landmark, the mobile nav drawer and the safe-area insets itself; `height="fill"` makes it 100dvh with independent scroll containers. Pages pad their own regions with `Layout`/`LayoutHeader`/`LayoutContent`/`LayoutPanel` token `padding` props — never add `px-*`/`py-*` classes to `<main>`.

## Astryx integration (UI toolkit)

The app is wired to the Astryx design system (`@astryxdesign/core` + `@astryxdesign/theme-neutral`, StyleX peer). This coexists with Tailwind v4 — do not remove either.

- **`globals.css`**: an `@layer reset, theme, base, astryx-base, astryx-theme, components, utilities;` declaration sits **above** `@import "tailwindcss"` (a `@layer` line below the import silently inverts the cascade). Astryx CSS imports follow: `reset.css` → `astryx.css` → `theme-neutral/theme.css` → `core/tailwind-theme.css` (token↔Tailwind bridge) → `theme-neutral/fonts.css`.
- **`providers.tsx`** (client): wraps the app in `<Theme theme={neutralTheme} mode={mode}>` + `<LinkProvider component={Link}>`, and publishes the mode through `ThemeModeContext` so `ThemeToggle` can hydrate from the same snapshot. Astryx components render unstyled without `Theme`. `layout.tsx` renders `<Providers>` inside the main column and passes `initialMode`.
- **`src/astryx-themes.ts`**: generated by `astryx theme add neutral` — do not hand-edit.
- **Dark mode is owned by `Theme`, not by an attribute**: what flips a surface is `html[data-theme]` — Lightning CSS compiles the neutral theme's `light-dark()` tokens into `var(--lightningcss-light, #f1f1f1) var(--lightningcss-dark, #1b1b1b)`, and `@layer astryx-theme`'s `html[data-theme="light|dark"]` rules (plus `:where(…)` copies in `reset.css`) set those two switches. With no `data-theme` on `<html>`, `color-scheme: light dark` + `@media (prefers-color-scheme)` answer instead — the reader's OS, not the button. The root `Theme` owns that attribute: its root sync **removes** it on the default `mode="system"`, which is exactly why `ThemeToggle` used to look dead (it hand-wrote `.dark` + `data-theme`; `Theme` stripped the attribute back off on mount and only the moon/sun glyph moved). `Providers` therefore renders `mode` from the store in `src/lib/theme-mode.ts` + `src/lib/theme-mode-context.ts` (`localStorage["theme"]` → the `theme` cookie → `prefers-color-scheme`) — the recipe `npx astryx docs use-a-theme` → *Dark mode* gives.
- **`layout.tsx` is async**: `seedThemeMode()` `await cookies()` for the `theme` cookie — the only mode a server can see — and `useSyncExternalStore` uses that seed for SSR **and** for the client's first pass, so `Theme` and `ThemeToggle` cannot hydrate into a different mode from the markup on screen (`useThemeMode` is the one hook both read). Reading `cookies()` opts the route into dynamic rendering, which every page here already chose with `export const dynamic = "force-dynamic"`.
- **Three stores, one mode** (`src/lib/theme-mode.ts`): `localStorage` (device choice, read by the pre-paint script), the `theme` cookie (what the server seeds from; `Providers`' effect keeps it equal to the mode it renders so the next navigation paints the same one), and `<html class="dark">` + `data-theme` (Tailwind's `dark:` hook and the browser chrome), written by `applyThemeMode`. `themeInitScript` (a string this module owns) seeds the last two **before** paint because `Theme` only syncs them once it hydrates. Only a *passive* effect may write `data-theme` — `Theme` writes it in a layout effect, so a passive one can re-assert a forced mode but never fight one.
- Follow the Astryx workflow block in the root `AGENTS.md` (`astryx build` / `component` / `doctor`) when adding or changing UI. Verify with `npm run astryx -- doctor --built <dir>` (it warns on raw `<div>`/`<svg>`/className — keep a raw element only where its native meaning is needed).

| Route | Screen | In left menu |
|---|---|---|
| `/` | Tổng quan: KPI toàn cục + tiến độ từng dự án | yes |
| `/projects` | Dự án: thêm dự án + danh sách | yes |
| `/projects/[id]` | Detail của một dự án (danh sách spec) | no (breadcrumb → `/projects`) |
| `/projects/[id]/specs/[slug]` | Spec + tasks | no (breadcrumb → project) |

Invariants:
- Menu active item is derived from `usePathname()`; `/projects/[id]` keeps "Dự án" active.
- Menu links are `<Link>` only — no client data fetching, no mutation.
- Detail routes are not menu items; they navigate back through breadcrumbs **and** an explicit `Back` button (see the spec page below).
- Thống kê chỉ lấy từ chuẩn Spec Kit (`listSpecs()` đọc `specs/<slug>/tasks.md`). Không còn route `/projects/[id]/tasks/[slug]`, không có screen nào hiển thị số liệu `tasks/<slug>/todo.md`; `/projects` chỉ render `specCount` + `StatsBadges` của spec.

- `/projects/[id]` is a **fixed-height board**: `AppShell height="fill"` gives `<main>` the viewport height and `Layout height="fill"` fills it — no hand-rolled `--content-h` measurement in `globals.css` any more, and mobile behaves the same as desktop (no breakpoint special-casing).
  - `header` = `LayoutHeader` (breadcrumbs + project name/path + `StatsBadges`), `content` = `LayoutContent` (scrollable) with the `List` of specs only; `end` = `LayoutPanel width={380}` with `AutoCheckLine` then `NotificationLog` (scrolls in place, heading stays). Each spec is a `ListItem`: slug (`type="code"`, `maxLines={1}`) left, `done/total` badge right (`—` when no `tasks.md`), and `RowProgress` (stock `ProgressBar`, `isLabelHidden`) as the row's second line — % stays double-encoded (bar width + badge text), colour never the sole channel. **Specs are the only progress source on every screen** — this page imports `listSpecs` only; the old `<project>/tasks/<slug>/todo.md` feature and its `/projects/[id]/tasks/[slug]` route are removed.

- `/projects/[id]/specs/[slug]` header row: `‹ Back` (`Button variant="ghost"
  size="sm"`, `icon={<Icon icon="chevronLeft" />}`, `href={`/projects/${id}`}`)
  sits left of the slug `h1` in an `HStack`, `RefreshButton` stays on the right.
  It is an **`href` Button, not `router.back()`** — `Button`'s `href` renders
  through `providers.tsx`'s `LinkProvider` → Next `<Link>`, so it is a plain URL
  navigation the server re-renders and it always lands on the project's spec
  list regardless of where the user came from (a deep link, a filter tab, an
  auto-refresh). `chevronLeft` is an Astryx semantic `IconName`, so it needs no
  `icons.tsx` lucide wrapper.
- `/projects/[id]/specs/[slug]` phases render as an Astryx `CollapsibleGroup`
  (`type="multiple"`, `hasDividers`, `density="compact"`, `defaultValue={[]}` =
  every phase collapsed on load, the old `<details>` default). Each phase is a
  `Collapsible` whose `trigger` is the phase title plus a `done/total` badge
  (badge counts the phase's **full** task stats, never the filtered list). When
  the "Chưa xong" filter is active the badge label flips to `pending/total`.
  Open/closed state lives inside `Collapsible`/`CollapsibleGroup`'s own client
  boundary — the page stays a Server Component (Astryx components carry their
  own `"use client"`, children arrive as an RSC payload), so there is no
  hand-rolled `<details>`/`<summary>` and no `border-*`/`bg-*` classes any more.
  - The trigger row carries the **same `RowProgress` bar as the spec rows** on
    `/projects/[id]` (`stats` prop = the phase's **full** stats, never the
    filtered subset); under the "Chưa xong" filter only the badge label flips to
    `pending/total` while the bar keeps showing **completed** %.
  - Task notes render as a per-row `Collapsible` with **no `value`**, so
    `useCollapsible` does not coordinate it with the phase accordion — each row
    keeps its own open state.
  - Filters are `SpecFilterTabs` (`src/components/spec-filter-tabs.tsx`):
    anchor tabs → `?status=done|pending`, so filtering deep-links, survives
    Back, and stays server-rendered.
  - The page mounts `<AutoRefresh intervalMs={job.intervalMs} enabled={job.enabled} />`
    (`auto-refresh.tsx`): same interval as the auto-check job, so the phase list
    + `AutoCheckLine` follow each tick; `router.refresh()` reconciles the same
    tree position, so scroll and an expanded phase's open state survive. Pauses
    while the tab is hidden. `AutoCheckLine` gets `autoRefreshing` so its
    footnote matches. Manual `↻ Làm mới` stays for instant refresh.
    `/projects/[id]` deliberately has **no** auto-refresh (manual only).
- `/projects/[id]/specs/[slug]` region split: the top block (breadcrumbs, `‹ Back`
  + slug `h1` + `RefreshButton`, `StatsBadges`, `AutoCheckLine`, `SpecFilterTabs`)
  is `topBlock`, rendered in `Layout`'s **`header`** slot (`LayoutHeader padding={4}`)
  so it still spans the **full** row; `Layout` sets **no** `contentWidth` —
  `/projects/[id]` doesn't either, and a capped width centred this page, giving
  it visibly wider left/right gutters than the spec list. Both pages now share
  the same gutter: full `<main>` width minus each slot's own `padding={4}`; only the phase
  `CollapsibleGroup` goes into `content` (`LayoutContent padding={4}`), and the
  `SpecSwitcher` `LayoutPanel` sits in `start` — i.e. **opposite the phase list
  alone**, no longer running up the left edge beside the title. `start` is
  `spec.hasTasks && …`, so the no-`tasks.md` `EmptyState` keeps the old
  full-width single column. `SpecSwitcher` rows use `Text type="code" size="sm"
  weight="semibold"` (bigger + bolder than the page's other code text) so the
  spec names read as the primary left-hand list.
